# ModChecker

Статический сканер Minecraft-модов. Он читает `.jar` как архив, разбирает
байткод через ASM и ищет подозрительные строки, вызовы и упакованные файлы.
Код мода не загружается и не выполняется.

Программа работает в двух режимах:

- без аргументов открывается окно Swing;
- с одним аргументом печатается консольный отчёт.

## Что делает

- проверяет строковые константы в `.class`;
- проверяет текст в `.json`, `.txt`, `.properties`, `.cfg`;
- смотрит вложенные `.jar` до двух уровней с полными путями;
- ищет известные строки: Discord/Telegram, данные аккаунтов и браузера,
  кошельки, Pastebin, Fractureiser;
- ищет простую маскировку строк: Base64, hex, переворот, XOR, сборку через
  `StringBuilder` и `char[]`;
- отмечает опасные вызовы: загрузку кода, `Runtime.exec`/`ProcessBuilder`,
  сетевые подключения, обращение к `APPDATA`/`user.home`;
- отмечает исполняемые файлы внутри jar;
- проверяет SHA-1 на Modrinth и отпечаток CurseForge;
- складывает находки в очки и выдаёт вердикт.

### Вердикты

- `ПОДОЗРИТЕЛЬНО` - 10 и больше очков.
- `ОК` - меньше 10 очков и файл подтверждён на Modrinth или CurseForge.
- `НЕИЗВЕСТНО` - меньше 10 очков, но подтверждения сайта нет.
- `ОШИБКА` - файл не читается как jar.

`ПОДОЗРИТЕЛЬНО` - не приговор. `НЕИЗВЕСТНО` - не гарантия безопасности.
Совпадение с сайтом означает только то, что файл совпал с официальной
страницей, а не то, что он безопасен.

## Требования

- Java 17 или новее.
- Windows, Linux или macOS.
- Для сборки отдельный Gradle не нужен: в репозитории есть Gradle Wrapper.

## Сборка

Windows:

```bat
gradlew.bat build
```

Linux/macOS:

```bash
./gradlew build
```

Готовый файл появится здесь:

```text
build/libs/modchecker.jar
```

Рядом с ним Gradle также копирует `README.txt`.

`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar` и
`gradle/wrapper/gradle-wrapper.properties` являются частью проекта. Их нужно
хранить в репозитории, иначе проект не соберётся у другого человека.

## Запуск

### Окно

После сборки откройте `build/libs/modchecker.jar` двойным кликом.

Если двойной клик не открывает jar, запустите его из консоли:

```bat
java -jar build\libs\modchecker.jar
```

В окне можно выбрать папку с модами или один `.jar`, перетащить папку/файл
мышкой, посмотреть таблицу, подробности по каждому моду и сохранить отчёт
в UTF-8 `.txt`.

### Консоль

С одним аргументом работает обычный консольный режим:

```bat
java -jar build\libs\modchecker.jar "C:\путь\к\mods"
java -jar build\libs\modchecker.jar "C:\путь\к\моду.jar"
```

Без аргументов открывается окно. Если аргументов больше одного, программа
показывает подсказку по запуску.

## Ключ CurseForge

Ключ нужен только для проверки отпечатка файла на CurseForge. Если ключа нет,
эта проверка пропускается, а Modrinth продолжает работать.

В окне есть поле ключа, кнопка `Показать`, кнопка `Проверить ключ`, галочка
`Запомнить ключ` и кнопка `Удалить ключ`.

Если включить `Запомнить ключ`, ключ сохраняется сюда:

- Windows: `%APPDATA%\modchecker\curseforge_key.txt`
- Linux/macOS: `~/.modchecker/curseforge_key.txt`

При следующем запуске GUI сам загрузит сохранённый ключ.

Старый способ тоже поддерживается: если сохранённого ключа нет, GUI ищет
`curseforge_key.txt` в папке запуска, затем в `~/.modchecker`. Консольный
режим ищет ключ по этим старым правилам.

Не кладите ключ в `build/libs`: команда `gradlew clean` удаляет папку `build`.
Ключ в корне проекта, в `%APPDATA%\modchecker` или в `~/.modchecker` переживает
пересборку.

Ключ никогда не выводится в консоль, отчёт или сообщения об ошибках.
Локальный `curseforge_key.txt` исключён в `.gitignore` и не должен попадать
в репозиторий.

## Что НЕ ловит

Это статический эвристический сканер, а не антивирус и не песочница. Он не
запускает мод и не видит, что мод делает во время игры.

- Не выполняет мод и не наблюдает его поведение.
- Не делает полную декомпиляцию и не восстанавливает весь код.
- Не строит полный граф потока данных и не эмулирует произвольный байткод.
- Не расшифровывает AES/RC4/кастомные шифры и сложную обфускацию.
- Не ловит строки, которые появляются только во время выполнения.
- Не ловит полезную нагрузку, скачанную позже, и код, загруженный с сервера.
- Не анализирует содержимое `.exe`, `.dll`, `.bat`, `.cmd`, `.ps1`, `.vbs`,
  `.scr`: правило 17 только отмечает сам факт наличия такого файла.
- Не ищет `.so`/`.dylib` отдельным правилом и не анализирует native-код.
- Не проверяет содержимое скриптов и не знает, что они делают.
- Не сканирует как текст `.yml`, `.yaml`, `.toml`, `.xml`, `.lang`, `.nbt`,
  `.dat` и другие форматы.
- Не смотрит вложенные jar глубже двух уровней.
- Не рекурсивно проверяет произвольные `.zip` и ресурсы, кроме вложенных `.jar`.
- Не ловит рефлексию, `MethodHandle`, `invokedynamic` и кастомные загрузчики
  классов, если в байткоде нет известных вызовов.
- Не ловит вредоносные действия через обычные API (например, удаление файлов),
  если для них нет отдельной сигнатуры.
- Не ловит неизвестные домены, кастомные протоколы, DNS-туннели и стеганографию.
- Не проверяет сетевой трафик и не видит, куда реально уходят данные.
- Не проверяет подписи jar, сертификаты и личность автора.
- Не определяет зависимости и их версии, не проверяет известные уязвимости
  (CVE) в библиотеках. Shaded-код просматривается только теми же строками и
  вызовами.
- Не находит логические бомбы, атаки по времени/условию и социальную инженерию.
- Не проверяет страницы сайтов вручную: только SHA-1/отпечаток файла.
- Возможны ложные срабатывания и пропуски.
